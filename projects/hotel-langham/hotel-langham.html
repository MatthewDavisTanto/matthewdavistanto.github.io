DATABASE DESIGN · ORACLE SQL

Hotel Langham Database System.

An academic database project modeling a hotel reservation system using ERD, relational database design, and Oracle SQL.

Project Overview

This project explored how a hotel reservation operation could be represented as a relational database. The system was modeled around hotel, room, guest, reservation, employee, and payment data.

Project Type Academic Database Project
Database Oracle SQL
Entities 8 Tables

Business Context

The database was designed around a hotel reservation environment where multiple hotels, rooms, guests, reservations, employees, and payments need to be connected and managed consistently.

The model supports relationships between hotel properties, room types, individual rooms, guests, reservations, reservation details, employees, and payments.

  • Hotel & room management
  • Guest & reservation records
  • Multi-room reservations
  • Payment records

COUNT · JOIN · GROUP BY

Hotel capacity

How many rooms are associated with each hotel?

+
SQL 
SELECT h.hotel_name,
                       COUNT(r.room_id) AS TotalRooms
                FROM hotel h
                JOIN room r
                ON h.hotel_id = r.hotel_id
                GROUP BY h.hotel_name;

DATASET NOTE

02
MAX · JOIN · GROUP BY

Highest payment

What is the highest payment recorded for each hotel?

+
SQL 
SELECT h.hotel_name,
                       MAX(p.amount) AS HighestPayment
                FROM hotel h
                JOIN room rm
                ON h.hotel_id = rm.hotel_id
                JOIN reservation_detail rd
                ON rm.room_id = rd.room_id
                JOIN reservation r
                ON rd.reservation_id = r.reservation_id
                JOIN payment p
                ON r.reservation_id = p.reservation_id
                GROUP BY h.hotel_name;
RESULT
Hotel Highest Payment

WHAT IT SHOWS

Combines five related tables through JOINs, then uses MAX and GROUP BY to identify the highest recorded payment for each hotel.

TECHNICAL NOTE

The query follows the relationship path from HOTEL to ROOM, RESERVATION_DETAIL, RESERVATION, and finally PAYMENT.
